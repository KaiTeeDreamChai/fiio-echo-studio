# 📖 SNOWSKY / FiiO Echo 音频文件规范与兼容性指南

> 本指南总结了针对 **SNOWSKY / FiiO Echo** 嵌入式便携无损播放器在实际使用中探索出的底层硬件解码特性、封面图像规范、歌词格式约束、文件系统目录排序原理以及全套工程化修复方案。

---

## 1. 硬件解码核心参数与限制

| 参数项目 | 官方标称上限 | 实测安全与最佳规范 | 异常表现与避坑要点 |
| :--- | :--- | :--- | :--- |
| **FLAC Block Size** | - | **$\le 4096$**（推荐 `4096` 或 `1024`） | **核心痛点**：网易云下载的母带/无损 FLAC 常采用 `Block Size = 8192`。播放器内部硬件解码帧缓冲区有限，遇到 $>4096$ 的音频帧会直接报 **“文件格式不支持” / “格式错误”**。 |
| **采样率 (Sample Rate)** | 192 kHz | 44.1 kHz / 48 kHz / 96 kHz / 192 kHz | 支持整倍率 PCM 解码，无需下采样。重构 Block Size 时务必保持原生采样率与 16bit/24bit 位深。 |
| **位深 (Bit Depth)** | 24 bit | 16 bit / 24 bit | 完全支持，无损 PCM 精度无损保留。 |
| **音频容器格式** | DSD/WAV/FLAC/APE/MP3 | FLAC (SQ/Hi-Res), MP3 (320 kbps) | 优先使用规范化后的 FLAC 或高质量 MP3。 |

## 2. 专辑封面（Album Art）嵌入规范

播放器内置的轻量图形处理器（GPU/Display Driver）对嵌入音频的图片解码较为严格：

* **分辨率限制**：必须为 **`500 × 500`** 像素。构建流水线以真实字节解析尺寸（网易云封面的 FLAC 元数据常写成 `0 × 0`，不可信），非 500×500 一律重新缩放。
  * 原生网易云 `1115 × 1115` 等超清大图会导致屏幕解码溢出，直接导致播放界面卡死、掉帧或封面黑屏。
* **图片编码格式**：**标准 Baseline JPEG**，严禁使用渐进式（Progressive JPEG）或非标准 PNG 格式。
* **色彩空间与色度抽样**：
  * **必须采用 `YUV 4:2:0`（`yuvj420p`）**。
  * 严禁 `YUV 4:4:4`（网易云原生常见规格，播放器图显模块无法正确解构）。
* **封面来源优先级**：音频内嵌图 → 网易云客户端下载目录下的 `meta/track-<曲目ID>.jpg`（离线、全尺寸原图）→ 数据库 `picUrl` 联网下载。三者都没有时才会保留无封面状态。
* **FLAC Picture 块类型**：
  * 必须标记为 **`Type 3`（Cover (front) / 正面封面）**。
  * `MIME Type` 设为 `image/jpeg`。
  * 必须保证音频文件内只保留 **1 张主封面**，避免多 Picture 块干扰。

## 3. 伴随歌词文件（.lrc）规范

播放器支持与歌曲同名的外部 `.lrc` 歌词联动显示：

1. **命名必须 100% 匹配**：
   * 歌词文件名（不含扩展名）必须与音频文件名完全一致（区分大小写及特殊标点符号）。
   * 示例：
     * 音频：`01 Frank Ocean - Nikes.flac`
     * 歌词：`01 Frank Ocean - Nikes.lrc`
2. **时间戳格式规范**：
   * 严格遵循 `[mm:ss.xx]` 标准双位小数格式（分:秒.百分秒）。
   * 过滤或清洗网易云歌词中偶现的 JSON 逐字元数据块（如 `{"t":1234,"c":[{"tx":"..."}]}`），将其转换为标准时间轴。
3. **文本换行与换行符**：
   * 换行符统一写为 `\r\n` (CRLF)。
   * 文件编码为 **UTF-8**（默认**不带 BOM**；若个别播放器需要 BOM，可设置环境变量 `FIIO_LRC_BOM=1`）。
   * 输入侧自动识别 UTF-8 / UTF-16 / GB18030 / Big5，避免老歌词乱码。

## 4. 存储介质与 FAT32 物理排序机制（FAT Sorter 原理）

由于嵌入式播放器芯片资源限制，文件浏览界面的曲目呈现遵循特殊规则：

### 现象
* 即使在文件名开头加上了 `01 `, `02 `, `03 `，播放器在打开某些专辑时依然可能显示乱序（例如先显示 `09`，再显示 `10`、`03`）。

### 底层机理
* 播放器**不会在系统内存中消耗 CPU 与 RAM 对整个文件夹内容做字母排序**。
* 它是直接读取 TF 卡（FAT32 文件系统）底层的**物理扇区目录项（FAT Directory Table）**。
* 普通的本地重命名操作只是在 FAT 槽位内更新字符串，并未重构扇区顺序。

### 解决规则
* **双位数字命名前缀**：专辑曲目采用 `{:02d} {Artist} - {Title}.flac` 规范化。
* **物理顺次重建（FAT Sorter，工作台已实现）**：
  * 在目标目录内建立临时暂存桶，把该目录下的文件全部移出目录项表。
  * 再按文件名升序，逐个移回原位，让驱动重新分配 `01..N` 的连续目录槽位。
  * 音频与同名 `.lrc` 一同处理；`._*`、`.DS_Store` 不参与排序，由 `dot_clean` 负责清除。
  * **注意**：目录项最终顺序仍由文件系统驱动决定，因此这是"尽力而为"的重建；工作台会如实回报处理了多少目录与文件，而不是只报成功。
* **清除 macOS 幽灵文件**：
  * macOS 读写 FAT32 会自动生成隐藏的 `._*`（AppleDouble）和 `.DS_Store` 索引文件。
  * 插入播放器前必须使用 `/usr/sbin/dot_clean -m` 彻底净化。

## 5. 标准化工程处理工具链参考

### 1. 音频重采样/重构帧（ffmpeg）
```bash
# 将 FLAC 帧限制在 4096（PCM 音质完全无损保留）
ffmpeg -y -i input.flac -map 0:a:0 -c:a flac -frame_size 4096 output.flac
```

### 2. 音频容器与封面（MP3）
```bash
# MP3 保持 .mp3 容器，不重命名为 .flac；封面通过 ID3 APIC（Type 3）写入
# 工作台会自动把 MP3 的 APIC 归一化为 500x500 / YUV 4:2:0
```

### 3. 封面标准化转换（ffmpeg）
```bash
# 生成 500x500，yuvj420p 色度采样的合规 JPEG 封面
ffmpeg -y -i raw_cover.jpg \
  -vf "scale=500:500:force_original_aspect_ratio=decrease,pad=500:500:(ow-iw)/2:(oh-ih)/2:black" \
  -pix_fmt yuvj420p -q:v 2 norm_cover.jpg
```

### 4. macOS 隐形文件清理
```bash
# 在终端中对挂载的 TF 卡音乐主目录进行清理
/usr/sbin/dot_clean -m "/Volumes/NO NAME/Musics"
```
